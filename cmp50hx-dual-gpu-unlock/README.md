# Dual NVIDIA CMP 50HX 20 GB compute unlock — Kali Linux / UEFI / GRUB

**Язык:** Русский | [English summary](README.en.md)

Практический отчёт и воспроизводимый набор вспомогательных скриптов для **последовательной вычислительной разблокировки двух NVIDIA CMP 50HX (TU102, 20 GB)** до запуска Linux, без модификации установленного драйвера NVIDIA и без перепрошивки VBIOS.

> **Основа проекта:** [xrip/cmp50hx-unlock](https://github.com/xrip/cmp50hx-unlock). Исходный UEFI-эксплойт, обработка GSP/SEC2 и firmware-пейлоады разработаны upstream. Здесь документированы и автоматизированы **выбор GPU по порядковому номеру обнаружения**, **два EFI-приложения**, **последовательный запуск из GRUB** и **повторное назначение one-shot меню после запуска Kali**. Это независимый экспериментальный сценарий, не официальный релиз автора upstream.
>
> **Предупреждение:** EFI-код обращается к защищённым механизмам GPU. При ошибке возможны зависание UEFI и необходимость полного выключения питания. Тестировать только с физическим доступом к машине и исправной резервной загрузкой. Используйте на собственном оборудовании и на свой риск.

## Проверенные результаты (10 октября 2026)

| Показатель | CMP 50HX №0 | CMP 50HX №1 |
|---|---:|---:|
| PCI BDF в тестовой конфигурации | `0000:03:00.0` | `0000:84:00.0` |
| PCI device/subsystem | `10de:1e09` / `10de:1554` | `10de:1e09` / `10de:1554` |
| VRAM | 20 480 MiB | 20 480 MiB |
| VBIOS | `90.02.60.00.1A` | `90.02.60.00.01` |
| FP32, ограниченная | 0.427 TFLOPS | 0.427 TFLOPS |
| FP32, после UEFI unlock | **13.5 TFLOPS** | **13.5 TFLOPS** |
| Ускорение FP32 | ≈31.6× | ≈31.6× |
| PCIe на момент проверки | Gen1 x4 | Gen1 x16 |

FP32 измерялась **clpeak / OpenCL** (`--single-precision-compute`). Сумма результатов двух независимых GPU ≈**27 TFLOPS FP32**. Это не показатель скорости одной распределённой задачи или LLM. Объём видеопамяти — **два независимых пула по 20 GB**, а не единый 40 GB.

**Проверено:** разблокировка каждого GPU отдельно, затем обеих в одной загрузке через GRUB, затем успешная загрузка с динамическими версиями и `grub-reboot`.

**Не проверено:** работа после холодного старта в каждом варианте, перенос в любые PCIe-слоты, другие ревизии CMP, добавление третьего GPU, стабильность под длительной CUDA/LLM-нагрузкой, PCIe Gen2/ReBAR. Результат FP32 не подтверждает производительность FP16/Tensor Core.

## Тестовая система

- **Плата:** Machinist X99-D8 Max; **CPU:** 2 × Intel Xeon E5-2680 v4.
- **GPU:** 2 × NVIDIA CMP 50HX 20 GB; дополнительно AMD Radeon RX 5700 XT (для вывода изображения).
- **ОС:** Kali Linux Rolling, ядро `7.1.5+kali-amd64`.
- **NVIDIA:** `615.71.09`; GSP Firmware `615.71.09`.
- **Загрузка:** UEFI, EFI System Partition (ESP) смонтирован как `/boot/efi`; GRUB.
- **Метод:** 2 экземпляра EFI Unlock с разными порядковыми номерами найденных CMP, `--return-to-grub`, одна цепочка GRUB.

## Как это работает

```text
UEFI firmware
    |
    v
GRUB (однократный next_entry=cmp50-auto)
    |
    +--> 50HX-AUTO0/50HXUNLK.EFI --return-to-grub
    |           \--> unlock 1-й обнаруженной CMP 50HX (ordinal 0)
    |
    +--> 50HX-AUTO1/50HXUNLK.EFI --return-to-grub
    |           \--> unlock 2-й обнаруженной CMP 50HX (ordinal 1)
    |
    v
GRUB обычное меню (default=обычная Kali)
    |
    v
Kali / NVIDIA 615.71.09
    |
    +--> systemd oneshot: grub-reboot cmp50-auto
                   (готовит следующий запуск)
```

Существует **два независимых бинарника**, собранных из upstream-исходника. Каждый выполняет одну разблокировку. Вспомогательный Python-скрипт удаляет быстрый список приоритетных BDF и использует одинаковое последовательное сканирование для обеих сборок; первая выбирает совпадение №0, вторая — №1. Устройство определяется по существующим проверкам upstream, а не по жёсткому BDF `03:00.0`/`84:00.0`.

> **Ограничение динамического выбора:** после перестановки слотов меняются порядок обнаружения и PCI-топология. При наличии ровно двух совместимых карт подход может сработать без редактирования BDF, но это **не подтверждено тестом после перестановки**. Не является безопасным механизмом hot-plug.

## Быстрый путь

1. **Изучить полный порядок действий:** [docs/INSTALL_RU.md](docs/INSTALL_RU.md).
2. Скачать upstream и подготовить сборочную среду.
3. Построить два EFI через `scripts/build-dual.sh` (скрипт **только собирает**, сам ESP не изменяет).
4. Разместить бинарники в **отдельных** каталогах ESP, не затирая исходную рабочую версию.
5. Создать отдельный GRUB-пункт из [`grub/42_cmp50_auto`](grub/42_cmp50_auto), проверить вручную.
6. Подтвердить FP32 обоих GPU через `clpeak`.
7. Только после ручного теста включить [`systemd/cmp50-auto-boot.service`](systemd/cmp50-auto-boot.service).

Минимальная проверка на собранном хосте:

```bash
sudo bash scripts/verify.sh
/home/kali/clpeak/build/clpeak --opencl --single-precision-compute
```

## Что это НЕ делает

- Не устанавливает/патчит драйвер NVIDIA, не изменяет VBIOS.
- Не включает PCIe Gen2, P2P или ReBAR. В испытании обе карты остались на PCIe Gen1.
- Не объединяет VRAM и не обеспечивает NVLink.
- Не гарантирует успешную загрузку при зависании прошивки.
- Не включает в репозиторий upstream-источники, firmware blobs, ROM-дампы или бинарники EFI (они собираются локально).
